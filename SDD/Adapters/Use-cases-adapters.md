# Use Cases Adapters — NexusMarket

## 1. Overview

Use case adapters live in `nexusmarket.adapters.useCases`. Each one is the concrete implementation of a role port of `nexusmarket.domain.ports.in` and bridges the incoming calls of the REST controllers (`nexusmarket.adapters.rest.controllers`, see [Rest-adapters.md](Rest-adapters.md)) to the domain services of `nexusmarket.domain.services`. Requests reach the controllers only after `SecurityConfig` and `JwtAuthenticationFilter` have authenticated the user and checked the route role (see [Rest-security-cors.md](Rest-security-cors.md)).

## 2. Responsibilities

* Implement exactly one role port.
* Inject the concrete domain service classes (`@Service`, constructor injection with `@RequiredArgsConstructor`).
* Delegate every call directly to the corresponding service; they contain no business rules.

```text
REST Controller (adapters/rest/controllers)
      |
      v  calls
Role Port (domain/ports/in)
      ^
      |  implemented by
Use Case Adapter (adapters/useCases)
      |
      v  injects & delegates to
Domain Service (domain/services)
      |
      v  calls
Output Port (domain/ports/out)
```

## 3. Transaction Management

Each use case adapter is the **transaction boundary** of its use cases: every operation runs in one Spring transaction (all or nothing). Domain services declare no transactions; the internal services they call (`ReserveInventoryService`, `GenerateInvoiceService`, ...) and the output adapters join the transaction of the use case, and no use case adapter calls another one.

| Annotation | Applies to |
| --- | --- |
| `@Transactional` (class level) | Every operation that changes state. If any step fails, every MySQL write of the use case is rolled back. |
| `@Transactional(readOnly = true)` | Queries and reports (methods `consult*`). |
| `@Transactional(noRollbackFor = PaymentRejectedException.class)` | `BuyerUseCaseImpl.validatePayment`: the only write before the rejection is its `PAYMENT_REJECTED` audit record, so the transaction commits and the rejection stays audited while the order remains `PENDING_PAYMENT`. |

Consequences:

* **Audit records** (MongoDB, outside the JPA transaction) are written after the commit; a rolled-back use case leaves no audit record (see [Persistence-adapters.md](Persistence-adapters.md), section 7).
* **Optimistic locking** of inventories, orders and carts compares the version read at the start of the use case; a concurrent modification fails the commit and the API answers 409 (see [Persistence-adapters.md](Persistence-adapters.md), section 5.6).
* The annotations are generated by `tools/gen_role_ports.py` together with the adapters.

## 5. Code Pattern

```java
package nexusmarket.adapters.useCases;

@Service
@Transactional
@RequiredArgsConstructor
public class AdministratorUseCaseImpl implements AdministratorPort {

    private final ChangeUserStatusService changeUserStatusService;
    // ...

    @Override
    public User changeUserStatus(User requestingUser, String userId, UserStatus newStatus) {
        return changeUserStatusService.changeUserStatus(requestingUser, userId, newStatus);
    }

    @Override
    @Transactional(readOnly = true)
    public User consultUser(User requestingUser, String userId) {
        return consultUserService.consultUser(requestingUser, userId);
    }
}
```
